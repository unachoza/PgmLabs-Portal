# Field Playbook

How to answer the fields conferences actually ask for. Match each form field to a row,
pull the right variant from `proposal-kit.md`, and respect the form's limits.

## Length routing (pick by the field's limit)

| Form asks for | Use from kit |
|---|---|
| Session title | §3 Title (or an angled variant — see below) |
| Short tagline / hook / "in one sentence" | §3 One-line hook or §3d Tiny abstract |
| Abstract ≤ ~200 chars | §3d Tiny |
| Description ~50 words / ≤ ~500 chars | §3c Short |
| Description ~100 words | §3b Medium |
| Description 150–250 words / "detailed" | §3a Long |
| Learning objectives / takeaways / "what will attendees learn" | §3 Learning objectives (3 bullets) |
| Speaker bio, short | §5 Short bio |
| Speaker bio, 100 words | §5 Medium bio |
| Speaker bio, "detailed" | §5 Long bio |
| Why this session / why now | Core story (§4) + a line on the AI-adoption gap for nonprofits |
| Session outline / agenda | The 7-step Innovation Journey (§4 framework), timed to the slot |
| Target audience | Nonprofit execs, community & entrepreneurship leaders, funders, technologists — all levels, designed for non-technical leaders |
| Format / session type | Match what the form offers; workshop shines at 60–90 min |
| Bio + org + contact + headshot | §1 Speaker profile (flag any `[FILL]`) |

## Angling the title per conference
Keep the core talk; tilt the title toward the event's audience:
- **Nonprofit leadership:** "From AI Consumers to AI Builders: Building Innovation Capacity in Nonprofit Teams"
- **Economic / workforce development:** "From AI Consumers to AI Builders: Hackathons as Regional Innovation Infrastructure"
- **Philanthropy / funders:** "Beyond Grants for Tools: Funding AI Capacity, Not Just AI Adoption"
- **Inclusive entrepreneurship:** "From AI Consumers to AI Builders: Inclusive Innovation for Underinvested Communities"
- **Civic / community innovation:** "From AI Consumers to AI Builders: Designing Community Hackathons That Stick"

Mirror the objectives to the same audience (swap "organizations" for "agencies," "grantees," "small businesses," etc.) without changing the substance.

## Common tricky fields
- **Character vs word limits:** count against whatever the form states; if it's silent, keep description ≤ 150 words and bio ≤ 100. Never overflow — trim to the next shorter variant instead of cutting mid-sentence.
- **Headshot / photo / logo upload:** cannot be auto-filled. Put on the Human checklist and point to §1 headshot path.
- **Video / prior-talk link:** use §1 past speaking; if none, offer to record a 60-sec intro or link the org site.
- **Co-presenter fields:** default is Alex solo. If the team wants a co-presenter (e.g. a co-facilitator), ask before adding.
- **Fee / honorarium / travel:** use §1 values; if `[FILL]`, ask once.
- **Demographic / DEI questions:** never assume — surface them on the checklist for Alex to answer.
- **Deadline / notification date:** capture into the Human checklist and the submissions log row.

## Auth-walled forms (expected, not an error)
Microsoft Forms "Invitation" links, Whova speaker portals, and login-gated Google Forms
usually can't be fetched. That's normal — ask Alex to paste the questions or share a
screenshot/PDF, then proceed exactly the same way.
